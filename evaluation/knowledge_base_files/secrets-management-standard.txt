Secrets Management Standard
Document owner: Platform Security
Review frequency: Annual
Classification: Internal

Purpose
Prevent credentials and tokens from being exposed through code, logs, documents, or evaluation artifacts.

Scope
Applies to application secrets, database passwords, signing material, and provider API keys.

Definitions
Control owner: the role accountable for implementation and evidence.
Exception: a documented, approved, and time-bounded deviation.

Roles and responsibilities
Secret owners define rotation.
Service operators provision runtime access.
Users report suspected exposure.

Mandatory rules
Never commit secrets or include them in URLs.
Do not log bearer tokens, password hashes, or provider keys.
Use individual or workload-scoped credentials.
Limit access to the service and operators that need it.
Rotate after exposure and remove stale credentials.

Operating procedure
Provision through protected deployment settings.
Verify the secret is absent from build output and response bodies.
Restrict runtime environment access.
Rotate and redeploy using approved procedure.
Review logs and source history after suspected leakage.

Examples
A redacted validation error reports field location but not secret content.
A test fixture uses a nonproduction placeholder.

Exceptions
Break-glass retrieval records custodian and expiry.
Exposed credentials trigger incident response.

Audit evidence and review
Audit secret lifecycle events without recording values.
Review privileged secret access quarterly.
